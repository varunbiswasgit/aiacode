# Testing — 02 Platform software

Manual test cases. Run each case, then tick the Pass column. Use test
VMs matching the target node roles.

| Setup | Action | Expected | Pass |
|---|---|---|---|
| Test VM, no Docker | Run 02-install-docker.sh, answer package for install_method and no to the registry mirror; repeat with installer method and a published checksum | sudo docker run hello-world succeeds, sudo docker compose version prints, no service account is in the docker group. With the installer method, the checksum is verified before the local copy runs; a mismatch aborts without running it | ☐ |
| Test VM, no Python 3.12 | Run 02-install-python.sh with a test venv path and a venv_base prompt | venv python --version shows 3.12, pip works inside the venv; a venv path whose parent is outside venv_base is refused before any mkdir or chown | ☐ |
| Test VM, repo exists on test Git server | Run 02-clone-project-repo.sh with test server and path | Project directory contains a git checkout on the requested branch | ☐ |
| DB test VM, no Postgres | Run 02-install-postgres.sh | postgresql service active, SELECT version returns 16 | ☐ |
| DB test VM, Postgres installed | Run 02-enable-pgvector.sh for the test database | CREATE EXTENSION vector succeeds, extension listed by dx | ☐ |
| DB test VM, Postgres plus pgvector | Run 02-create-databases.sql via psql with -v docs_db, standards_db, audit_db and app_user and the app password read silently into PGPASSWORD with read -s (never via -v app_password) | Three databases exist, app user can connect, app user has no superuser rights and holds USAGE only on the schemas (no CREATE) | ☐ |
| DB test VM, Docker installed | Run 02-install-qdrant.sh, answering the bind-IP, digest-pinned image and API-key (read -s) prompts | Container running with ports published only on the prompted internal IP, health endpoint requires the Api-Key header and returns version JSON with it; an existing container is recreated with its volume preserved. An untagged or latest image and 0.0.0.0 as bind IP are both rejected | ☐ |
| DB test VM, Docker installed | Run 02-install-redis.sh, answering the bind-IP, digest-pinned image and password (read -s) prompts | With REDISCLI_AUTH set, redis-cli ping returns PONG, data persists after container restart; without the password the ping fails. An existing container is recreated with its volume preserved; a mutable tag such as redis:7 and 0.0.0.0 as bind IP are both rejected | ☐ |
| GPU test VM, driver working | Run 02-install-ollama.sh, answering the bind-IP prompt (0.0.0.0 rejected) and, when Ollama is not already installed, the installer SHA256 and yes confirmation | ollama --version works, API tags endpoint answers on the prompted internal IP only; a checksum mismatch or anything other than yes at confirmation aborts without running the installer | ☐ |
| GPU test VM, venv present | Run 02-install-vllm.sh with an exact pinned version (default example 0.31.0) | python -c import vllm prints exactly the pinned version (any other installed version aborts), nvidia-smi lists the GPU, a freeze lockfile is written; with a hash-verified lockfile supplied, install uses pip --require-hashes and a mismatched pin aborts | ☐ |
| App test VM, app not yet running | Run 02-install-nginx-tls.sh, complete the CSR step with a test CA | nginx -t passes, HTTPS site proxies to the upstream port, HTTP redirects to HTTPS, TLS is 1.2/1.3 only with an HSTS header, the primary verification runs without -k (the -k check is only the marked pre-CA fallback), and the CSR file is deleted once the signed certificate exists | ☐ |
| Test VM, Docker installed | Run 02-configure-log-aggregation.sh with test SIEM | Test logger message and container log arrive in the SIEM search | ☐ |
| All three test nodes up | Run 02-platform-smoke-test.sh from the app node with test hostnames, answering the optional Qdrant API key prompt (blank = try without) | All checks print OK, script exits 0. With a key-protected Qdrant and a blank key answer, the Qdrant check prints the distinct auth-required (401) message and still counts as failed | ☐ |
| DB test VM, registry and audit tables created | Run 02-grant-database-permissions.sh with test admin/app usernames | INSERT and SELECT are granted on clauses, clause_changes, audit_log, feedback and review_decisions (and suggestions when it exists); no UPDATE or DELETE is granted; a missing table is warned about and skipped, and the script exits non-zero if a grant fails | ☐ |
